# Songpa explicit production-mode technical successor

This successor reuses the existing owned-repository Gangnam release boundary, output validator, mutation tests and control approach. No framework or dependency was added. `package-lock.json`, every `src/data` file, the frozen runtime validator, all reviewed customer copy, and all 11 product/banner images remain byte-identical to the 69-file accessibility preview. Existing research, plan and copy evidence is historical and unchanged.

The original README describes the frozen preview history. The added technical layer implements public metadata separately and does not change those records or claim their false publication/ownership flags became true. Default mode remains preview with all five HTML routes noindex, deny-all robots, the exact empty sitemap, and reserved invalid canonical origin. The original assert_preview_boundary.mjs remains intentionally preview-only.

Explicit production mode requires SITE_RELEASE_MODE=production, SITE_INDEXABLE=true, the exact https://seoul-songpa.fwith.kr origin, a pinned source revision, and a SHA256-bound production-binding.json outside the source root. The existing public IndexNow proof is reused byte-for-byte; no new proof key or credential is generated. Builds reject Cloudflare account/API credential variables and unbound approval flags. Source code does not contact the provider, attach a host, deploy, or submit IndexNow.

The exact intended public presentation is derived from frozen presentation-contract.json:
- Home and the condolence/wedding articles: index,follow; exactly these three sitemap URLs.
- /regions/: noindex,follow, self-canonical, omitted from sitemap and primary navigation.
- /404.html: noindex,nofollow,noarchive, no canonical or social metadata. Actual HTTP 404 remains a deployment/loopback verification obligation.

`npm run build` verifies frozen input/projection, Astro diagnostics, release metadata, customer HTML, and image bytes. `npm test` exercises native boundary tests and compiled copy mutations in either mode. `npm run test:production` additionally checks the actual production artifact and metadata/proof/sitemap corruption fixtures. An exact 23-file production inventory is required.

Local production fixture bindings use synthetic commits only in the separate local-test-only directory. They are test inputs, not approval/provider readback evidence. Remote source commit/tree, authorization reference, provider ownership/binding, actual runner browser results, public HTTP/404 and IndexNow receipt require their own verified evidence before release completion.
