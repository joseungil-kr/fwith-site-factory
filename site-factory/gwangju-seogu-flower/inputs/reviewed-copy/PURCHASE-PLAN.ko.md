## [추정·판단] 본문 순서와 구매 질문의 답

서구는 기본가격만으로 전체 주문 비용을 확정할 수 없는 상황이다. 주소 대조로 시작하지 않고 첫답변에서 조의를 전할 상품과 가격 범위, 짧은 인사를 제시한 뒤 다음 순서를 쓴다.

- 전체예산: 기본가와 배송비 포함 최종금액을 구분한다. 네 가격대 사이의 20,000/30,000/40,000원 차이는 단순 산술이며, 가격으로 꽃 수량·높이·품질을 추론하지 않는다. 다음 행동은 총예산 기준 전화 상담이다.
- 상품사진: 실제 네 사진에서 보이는 색·윗장식만 설명한다. 4개의 카드와 각각의 공식 상품 URL이 이어진다. 특정 소재 확정이나 크기 차이는 말하지 않는다.
- 리본: 짧은 조의 인사, 보내는 이름, 회사·모임 예시를 설명한다. 고객의 경험·감정·종교를 지어내지 않는다. 상품과 문구를 함께 상담하는 다음 행동으로 연결한다.
- 장소·일정: 운영자 원문과 정부 명부가 겹치는 주소·대표번호만 간결히 제공한다. 실제 반입·수령·전달 시각은 개별 주문 상담 대상으로 남긴다. 시설 전화와 꽃이랑의 상담 전화를 혼동시키지 않는다.
- 주문정보: 상품/전체예산, 빈소·고인 또는 상주명, 희망일정·발인, 리본·보내는 이름·주문자 연락처를 4개 항목 한곳에 묶는다. 실제 고객정보를 수집하거나 공개한 것이 아니다. 상품·리본만 먼저 상담할 수 있도록 썼다.
- FAQ 3개: 희망 도착시각의 의미, 수정·취소 시 제작/출고 구분, 소재 차이와 하자·오배송의 정책 차이를 보완한다. 본문 가격을 FAQ로 다시 복제하지 않는다.

문자수는 고유 본문 2,218자, FAQ와 마무리를 합쳐 2,940자다. 공통 카드·메뉴·출처·CTA·heading은 제외했다. 약2,500~3,000자 목표를 참고했지만 본문만의 숫자를 맞추려고 문장을 덧붙이지 않았다. 고객에게 필요한 질문과 조건을 모두 포함하는지를 독립 검토자가 별도로 평가해야 한다.

## [추정·판단] 내부 의미 중복 검토

동구·나주·광양의 실제 고객 원고와 비교했다. 같은 꽃이랑 네 상품과 정책·상담 번호·리본 예시의 의미는 공통일 수밖에 있다. 이를 억지로 다른 사실처럼 만들지 않았다.

- 동구는 조선대병원 운영·반입의 불확실성과 병원/대학 자료를 다룬다. 서구는 읽을 수 있는 국빈 운영자 오시는길과 정부 행의 일치라는 별도 근거를 사용하고, budget → products → ribbon → facility → order로 순서를 새로 정했다.
- 나주·광양의 10,000원 추가배송비와 합산 예산은 서구에서 사용할 수 없다. 서구는 구체 합산액을 만들지 않고 상품값 차이와 전체예산 상담으로 가격 결정을 설명한다.
- 리본 예시나 소재·환불 정책은 공통이지만 문단·카드·도입을 지역명 치환으로 생성하지 않았다. 홈도 budget → facility-guide → consultation 순서다.
- 엔티티를 가린 20글자 shingle 겹침은 동구0.003160, 나주/광양/순천0이다. 20자 이상 동일 문장은 네 비교 대상 모두0개다. 이 수치는 어휘적 비교이며 의미 차별성·구매 효용의 합격 증거가 아니다.

## [직접 확인/도구 보고] 기존 기술과 자산 재사용

동구의 실제 JSON 및 CopyPage/ProductCards/SharedFlowerBanner 구조를 읽었다. 문장과 시설명 치환 없이 machine schema와 렌더 사양 필드, 접근성 공통 라벨, 승인 배너 alt·7개 이미지 바이트를 재사용했다. home의 시설 카드 위치는 기존 index0이 아니라 id=facility-guide다. 원고 구조를 따르도록 구현 담당자에게 전달했다.

선행 GitHub 조사 기록에서 [Astro](https://github.com/withastro/astro)와 [storefront](https://github.com/withastro/storefront)의 실제 LICENSE 내용을 읽었다. MIT이며 Astro에는 upstream 고지도 포함된다. 2026-10-15/2024-10-21 최근 push와 archived=false·TypeScript는 도구 조회 기록이고 건강한 유지보수의 보증은 아니다. 이미 검증된 자체 Astro 구조가 현재 정적 상담 안내에 맞으므로 새 스토어·결제·설치를 추가하지 않는다.

배너 3개는 승인 정본과 동일 SHA,1774×887이다. 상품사진4개는 각500×500이다. 자산 출처·바이트·SHA와 관찰 범위는 asset-manifest.json에 있다. 배너와 사진은 새로 생성·수정하지 않았다.

## [기술 계획] 구현 때 검증할 것

render-plan.json은 계획이다. 앱 코드나 HTML을 만든 것은 아니다.

- H1 각1개, section H2 아래 카드/FAQ H3, 출처 H2 하나
- 홈·상세에만 message → budget → consultation 3배너, 실제 본문·카드 사이 분산

- 4상품 각각 실제 사진과 정확한 SKU URL, FAQ3개 각각 항상1회 노출

- 상세 breadcrumb home→support→current, support inbound 최소1, 허위 추가 시설 링크 없음
- 배포 origin 확인 전 canonical/domain/origin null, productionEnabled=false
- 공개 시 홈/상세 sitemap2, support와404 noindex; actual404·공개자산SHA·실제 화면은 별도 검증

Google/네이버 원문도 읽었다. 고유하고 유용한 정보, 정확한 제목과 텍스트·alt, 무의미한 유사지역페이지·키워드반복 방지를 적용한다. 2,500~3,000자는 검색엔진 최소기준이 아니며 IndexNow 접수도 실제 색인·순위와 구별한다.

## [미확인] 완료 표현의 경계

배송비·최종금액, 실제 화환 반입·수령, 전화 연결·재고·주문·배송은 미확인이다. 원고·사양의 로컬 검사와 독립 검수는 앱 구현, source commit, build, 실화면, 공개HTTP, IndexNow의 성공을 뜻하지 않는다. 앱/원격쓰기/issue/배포/PC/CodexWork/API 콘텐츠 생성/새이미지/설치는 수행하지 않았다. 후속 구현은 최종 원고 digest와 독립 검수의 일치 확인 뒤 별도 담당자가 진행한다.
