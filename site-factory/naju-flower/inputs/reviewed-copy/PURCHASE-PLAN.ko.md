## 구성과 재사용

홈은 단일 상세로 연결하는 짧은 탐색·상담 페이지로 두고 같은 장문을 복제하지 않는다. 상세는 배송비 포함 예산 → 실제 상품 → 시설 식별 → 리본 → 주문·일정 → 변경·취소 → FAQ 3개 흐름으로 작성한다. 고유본문 2,500~3,000자는 상세 초안 목표다. 홈·support·404까지 같은 길이를 강제로 늘리지 않는다.

JSON 한 파일을 고객 문구 단일 원본으로 사용하며 Markdown은 검토용 출력이다. 홈·상세 외 단일 자식 support와 404 문구도 함께 검토한다. support는 noindex/사이트맵·메인메뉴 제외, 404는 noindex/실제 HTTP 404, 두 페이지 모두 배너 0개를 계획한다. 초안의 모든 canonical/origin은 미배정이다.

순천의 구조·FAQ 단일 렌더·상품 상세 CTA·승인 배너 3종을 재사용한다. 선행 GitHub 조사 원문도 읽었다. withastro/astro는 TypeScript 중심, 보존 pushed_at 2026-10-14, MIT 및 부분별 라이선스다. withastro/storefront는 MIT·TypeScript이나 pushed_at이 2024-10-21이다. 자체 검증된 Astro 구성과 라이선스 표시를 유지하는 편이 적합하다. 이번에는 새 프레임워크·주문 API·콘텐츠 생성 API를 도입하지 않는다.

## 검토와 종료 조건

작성자 점검은 원문·수치·문구·JSON/Markdown 일치·사진/배너 해시·중복도까지다. 독립 검토자는 최종 고객 전문과 메타·카드·버튼·FAQ·alt를 읽고 문체와 정보 완결성을 각각 판정해야 한다. 구현·실제 HTML·모바일·공개 HTTP·검색 접수는 후속 단계이며 초안 PASS로 대체하지 않는다.
