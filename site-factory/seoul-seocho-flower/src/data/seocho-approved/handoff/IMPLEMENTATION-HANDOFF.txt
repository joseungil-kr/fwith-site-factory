서초구 로컬 계획과 고객 원고 구현 인계

1. 상태와 작업 경계
이 인계는 독립 검토한 서초 계획·고객 원고·정본 자산을 이후 승인된 구현에 전달하기 위한 로컬 자료다. 원고 검토 결과와 최종 digest는 acceptance.json을 기준으로 한다. 수록됐다는 사실만으로 구현 또는 공개를 승인하지 않는다.
서울 관악구 미완료 작업과 실패한 QA가 별도로 남아 있다. 이 로컬 서초 작업으로 관악 상태, 전국 공개 분자, source 소유권, 현재 Git 승인상태를 바꾸지 않는다. 원격 Git 쓰기·새 source 브랜치·커밋·푸시·배포·IndexNow·Airtable·v2·AI API 작업은 수행하지 않았다.
연구패킷이 조회한 main은 f30375041d97d958493ca74b0c4220d8ab85fc4b이며 재사용 패턴의 자료원 source는 4f982994513cb7913f869b0114b3427be50b1362다. 이 작성자는 현재 원격 ref를 새로 조회하지 않았다. 특히 후자는 관악 QA 실패 상태의 자료원이므로 정상 실행이 검증된 템플릿으로 취급하지 않는다. 이후 구현자는 부모가 승인한 실제 작업환경·소유권·현재 ref와 수정 완료본을 확인한 후 시작한다.

2. 입력의 의미
plan/fixed-plan.json이 최초 동결된 originalPlanN = 2와 두 URL을 고정한다. 후보 원본 candidate-plan.json,8개 후보군,7개 별도 URL 보류결정은 모두 보존했다. plan/membership.json은10개 법정동·18개 행정동·23개 관계다. 행정구역·시설·상품·앵커 개수를 글 수에 더하지 않는다.
copy의 최종 article/common JSON, 검토서 및 handoff/acceptance.json이 고객에게 보여줄 정확한 텍스트를 결속한다. runtime-input.json은 이 입력을 합친 전달용 데이터일 뿐 실제 소스에 저장·실행한 결과가 아니다. 내부 metadata/evidence/bindings/renderRule/visibilityContract를 고객 HTML에 출력하지 않는다.
아직 사이트 소스 SHA, canonical hostname, 빌드 또는 공개 URL이 없다. sourceHash·productionApproved·hostnameOwnershipVerified·배포완료·색인 상태를 임의로 채우지 않는다.

3. 구매 문서와 길찾기
근조: /regions/seocho-funeral-wreath/
축하: /regions/seocho-celebration-wreath/
홈 /, 목록 /regions/,404 /404.html을 포함하면 예상 HTML 경로는 5개다. 이 경로들은 아직 생성하지 않았다.
근조 글 안의 seoul-st-mary-funeral은 서울성모장례식장 정보다. 축하 글의 eltower, at-center-exhibition은 서로 다른 물리 장소 정보이고 opening-relocation은 구매상황이다. opening-relocation을 시설로 만들거나 주소/동을 배정하지 않는다.
시설 독립URL, 별도의 개업/이전URL, 법정동별 키워드URL은 만들지 않는다. 검색 질의 18개나 후보군 8개가 발행할 글 18개·8개를 의미하지 않는다.

4. 지역 사실과 보류
서울성모장례식장: 반포대로 222, 반포동 505. 법정동 반포동 1165010700. 지상 1~3층 안내는 빈소 번호나 현재 입실상태의 대체값이 아니다. 판매자 1844-0644와 장례식장 02-2258-5940을 구분한다. 병원 대표번호나 시설주소를 꽃이랑 사업장 정보로 구조화하지 않는다. 부고 실명·관계·일정을 원고/소스에 가져오지 않는다.
엘타워: 강남대로 213, 양재동 24. 법정동 양재동 1165010200. 그랜드홀 7층·그레이스홀 6층·오르체홀 5층·엘하우스홀 8층. 일반 물품 사전발송 협의 규정은 화환 반입 허가가 아니다.
aT센터: 강남대로 27, 양재동 232. 법정동 양재동 1165010200. 제1전시장 1층·제2전시장 3층. 전시물 반출입신고서를 모든 꽃배달의 의무서류로 일반화하지 않는다. aT 웨딩은 현재 생화·조화 혼합상품 반입 조건 미확인으로 계속 보류하며, 해당 예식장 주문 안내를 진행하지 않는다. 고객에게 조건 확인을 지시하거나 확인 후 상담으로 판매를 재개하는 문장을 복원하지 않는다. 판매자의 추가 확인 대행도 약속하지 않는다. 2017년 예고를 2026년 전체시설 금지 또는 허용으로 바꾸지 않는다.
예술의전당: 한가람미술관·한가람디자인미술관·서울서예박물관 대관 전시장과 로비 등 부속 실내공간의 화환금지를 정확히 유지한다. 공연장·야외·건물 전체로 범위를 넓히지 않고, 로비나 다른 꽃상품을 우회안으로 제안하지 않는다. 이 보류시설을 판매용 시설링크로 승격하지 않는다.
시설 3개 모두 행정동은 null이다. 법정동↔행정동 관계로 개별 시설의 행정동을 추정하지 않는다. 특히 행정 반포3동은 법정 잠원동과 관계가 있다. 서초3동은 서초동·방배동, 양재1동은 양재동·우면동, 양재2동은 양재동·원지동, 행정 내곡동은 내곡동·염곡동·신원동과 관계가 있다. 나머지 8개 법정동에 가짜 시설을 채우지 않는다.

5. UI와 데이터 소비
기존 관악 인계와 호환되는 articles/common 구조를 사용한다. 이는 원고구조 호환성이지 관악 런타임 QA 통과를 의미하지 않는다.
- [category]/[slug] 상세: id 또는 slug로 정확히 한 글을 선택한다. firstAnswer를 한 번 출력하고 sections의 제목·문단·순서를 유지한다. contentMarkdown과 sections를 동시에 출력하여 본문을 두 번 만들지 않는다. 제품 section.productCardSkus의 실제 4개 카드를 결합한다. FAQ 배열의 question/answer가 조건문 때문에 빠지지 않게 한다.
- 홈: common.home의 title/H1/meta/intro/shortTalk, 구매카드 2개, 제품 8개, exact CTA를 쓴다. 이전 지역·상담시간·배송약속을 상속하지 않는다. 첫 문장에 실제 상품과 기본가격으로 답한다.
- ProductCards: name/priceLabel/description/imageAlt/cta/photoCaption을 그대로 쓴다. priceLabel의 금액을 다시 이어붙이지 않는다. CTA는 8개 검증된 개별상품 URL이며 공식몰홈이나 가짜 주문 버튼으로 대체하지 않는다. 새 주문/결제는 이 인계 범위가 아니다.
- RegionDirectory: 실제 구매카드 2개를 한 번씩만 노출한다. 법정동 표와 물리시설 링크를 분리한다. 반포동에는 서울성모, 양재동에는 엘타워/aT 전시의 factual anchor만 둔다. 일반 근조·축하 링크는 지역 내 실제 배송이력·배송가능 보증이 아니다. 카드 수를 맞추려고 시설·동을 복제하지 않는다.
- 헤더/푸터/404: common navigation,footer,notFound,accessibility,articleUi의 exact copy를 쓴다. 404 title과 h1은 별개 값이다. 본문 바로가기·주요 메뉴·현재 위치 3개 문구가 실제 포커스 동작을 보증하지 않는다. 고객 문구를 추가하면 독립검토 대상이다.
- 글에 이미 있는 가격·소재·수거·일정·취소안내를 경고상자/FAQ/고정푸터에 중복 출력하지 않는다. 홈은 priceNote 1회와 상품 하단 소재·수거 고지 1회. 승인된 상품별 사진설명은 원래 역할을 유지한다.

6. 상품과 배너
근조 B201 59,000원 / B203 79,000원 / B205 109,000원 / B060 149,000원. 축하 C200 59,000원 / C203 79,000원 / C204 99,000원 / C205 149,000원. 모두 상품 기본가격이며 총액이 아니다.
8개 실제 판매사진 500×500과 공통 배너 3개 1774×887은 approved-assets.json의 exact bytes와 digest로 전달한다. 판매사진에 AI 배너를 대신 쓰지 않는다. 사진의 크기·품질·꽃 수량·소재비율·행사장 납품을 추론하지 않는다.
공통 배너는 message→budget→consultation 순서로 실질 본문/제품/FAQ 사이에 분산한다. 디자인·문구·alt·AI고지·비율을 바꾸지 않는다. 원래 공개배너 HTTP/MIME/bytes 검증은 이후 공개 승인과 실제 배포 뒤에 수행한다.
N = 2 목록은 기존 items.length<3 조건 아래 noindex,follow·sitemap 제외·배너 0개를 유지한다. 미공개 빌드는 전경로 noindex,nofollow,noarchive와 빈sitemap이 정상이다. 404배너 0개다. helper의 2카드 분산 가능 경계와 원래 배너 요청 조건 >= 3을 혼동하여 N = 2 목록에 배너를 켜지 않는다.

7. 구현 후 검증할 것
현재 수행하지 않은 검증이며, 원고 검토 PASS로 대신할 수 없다.
- 승인 입력 해시→실제 소스의 input binding→빌드 HTML 5경로의 모든 노출문구를 정확히 대조한다.
- 상세별 H1 하나와 H2/H3 순서, firstAnswer 1회, source 영역 하나, 실제 FAQ 질문·답변, 섹션/앵커, 상품 4개씩·홈 8개, 전화·공식몰·개별상품 CTA, 관련링크를 점검한다.
-10/18/23 지리관계와 3시설의 법정동/행정null, 구매상황 앵커의 비시설 취급, 후보·보류·originalPlanN 보존을 검증한다.
- 전체 예상 경로 5개를 분모로 유지하고 noindex/목록/404 예외를 명시한다. 누락·중복기사, 부정확한시설귀속, 구지역문구, 정책누락, 가격오류, 상품/배너변조, 잘못된canonical·robots·sitemap·CTA를 거부하는 음성시험을 둔다.
- 최종 source SHA로 빌드와aggregate QA를 실행한다. 관악의 미해결 키보드/고정header/footer 회귀를 그대로 가져오지 않도록 실제 320/390/1280 화면과 키보드/앵커 이동을 직접 확인한다. 원 단위 줄바꿈·가로overflow·가려진H2/H3·CTA·푸터·404를 확인한다.
- 필수 승인 후 공개한 경우에만 실제 HTTP 200/404,canonical,robots,sitemap,상품·배너 MIME/SHA/크기를 다시 확인한다. IndexNow 영수증과 실제색인·노출·순위는 별개로 기록한다.

8. 남은 확인 범위
원문은 공식사이트에 게시된 상품/정책/시설자료를 뜻한다. 실제 재고·일정이행·현장반입·총액·설치·완료사진·제휴·거래성공은 확인하지 않았다. 수거는 판매자 원문상 제공하지 않으므로 미확인 서비스처럼 복원하지 않는다. 모든 새 사실이나 변경문구는 근거·독립검수·정확한digest를 다시 결속한다.
