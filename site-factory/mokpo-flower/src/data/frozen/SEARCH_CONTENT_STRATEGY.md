# 지역 페이지 검색·정보 완결성 제작 기준

적용: 2026-10-13 사용자 지시. 다음 신규 지역인 서울 강서구부터 적용한다. 기존 지역의 정보 확장·FAQ 수리는 별도 후속 범위이며 이번 노원은 기존 4글의 승인된 문체 수정본 배포를 완료한다. 공통 이미지 배너의 승인된 별도 작업은 자체 소유권·검수·배포 흐름으로 진행하며 이번 노원 완료 범위를 자동으로 확대하지 않는다. 기존 계획 분모·URL·시설/의도·보류 이력을 보존한다.

## 작성 전에 조사하고 설계할 것

1. 대표 검색어와 세부 검색어를 실제로 검색하고, 사용자가 지금 해결하려는 구매 결정과 구매 단계를 적는다. 검색량이나 순위를 측정하지 않았다면 추정값을 만들지 않는다.
2. 기존 내부 문서를 대조해 같은 시설·의도에 여러 URL이 경쟁하는지 확인한다. 동의어는 한 문서로 묶고 서로 다른 구매 결정은 분리한다.
3. 실제 경쟁 페이지의 본문을 읽어 어떤 질문에 답하고 무엇이 빠졌는지 비교한다. 검색결과 제목만 보고 경쟁 본문을 읽었다고 하지 않는다. 경쟁사의 실적·정책을 자사의 서비스 약속으로 가져오지 않는다.
4. 원본 공식 지역·시설자료, 검증된 상품과 가격, 현재 업체 정보에서 사용할 사실을 추린다. 지역명만 바꾸는 복제를 금지한다. 기존 코드·오픈소스·스타터/API 사례의 재사용 검토도 기존 절차대로 수행한다.
5. 핵심 첫 답변, 본문 정보 순서, 실제 상품 선택 이유, 내부링크의 다음 결정, 전화/상품 CTA를 계획한다. 허브나 글 수를 먼저 정해 분량을 채우지 않는다.

## 풍부한 내용을 쓰는 방식

짧게 압축하는 것 자체를 목표로 삼지 않는다. 고객이 이해하고 결정하는 데 필요한 설명을 충분히 쓴다. 공통 메뉴·상품카드·푸터를 제외한 고유 본문은 약 2,500~3,000자를 기본 초안 목표로 삼는다. 이는 랭킹 공식이나 기계적인 최소 통과선이 아니다. 목표에 못 미치면 정보 공백을 검토하고, 근거 없는 문장이나 반복으로 분량을 늘리지 않는다. 더 긴 설명이 필요하면 충분히 쓴다.

글마다 필요한 다음 내용을 근거와 함께 설명한다.
- 도입: 누구에게 무엇을 왜 보내는지 직접 답하고, 상황을 존중하는 짧은 공감으로 상담에 연결한다.
- 장소: 주문에 실질적으로 도움이 되는 해당 시설의 주소·건물/공연장·수령 조건·실제 반입 제한. 관광·인구·역사로 지역성을 꾸미지 않는다.
- 상품: 확인된 실제 상품사진·상품명·기본가격과 예산별 선택. 확인되지 않은 크기·꽃 수량·품질·수명 차이를 가격에서 유추하지 않는다.
- 비용과 배송: 기본가와 총액, 추가 배송비 조건, 실제 확인 가능한 주문 확정 절차와 희망 시간의 의미. 당일/정시/무료/설치/회수/완료사진 제공을 발명하지 않는다.
- 주문: 필수 정보를 한 곳에 모으고, 목적에 맞는 리본 문구 예시와 상담 방법을 충분히 설명한다. 고객에게 같은 확인 숙제를 반복하지 않는다.
- 변경·취소: 확인된 업체 정책만 설명한다. 빈칸이 구매 결정에 필수이면 필요한 질문으로 남기며 임의의 환불·취소 규칙을 만들지 않는다.
- FAQ: 본문에서 덜 설명된 실제 구매 질문에 구체적으로 답한다. 개수 채우기나 본문 반복을 피한다.
- 링크: 다음 구매 결정에 맞는 관련 문서·실제 상품·상담으로 연결한다. 관계없는 시설 목록이나 전국 footer 링크를 늘리지 않는다.

미확인 사업 정책이나 상품 사양이 필요하면 원본을 더 조사하고, 여전히 필수 정보가 없을 때만 사용자에게 필요한 질문을 한다. 확인되지 않은 약속으로 정보를 채우지 않는다. 친절함·제공자 시점·짧은 스몰토크 기준은 SALES_COPY_ACCEPTANCE.md를 함께 따른다.

## 독립 검수와 실제 출력 검사

문체의 친절함과 검색·정보 완결성은 별개로 평가한다. 작성자와 다른 검토자가 검색 의도별로 질문→답변→근거→다음 행동을 대조하고, 실제 고유 본문의 정보량과 형제 문서 중복도를 기록한다. 핵심 질문이 빠졌다면 글이 길어도 충분하다고 판정하지 않는다. 기존 PASS나 단순 문자수 점수로 대신하지 않는다.

2026-10-12 노원·양천 감사에서 확인된 사항을 회귀 검사로 남긴다.
- 양천 데이터의 FAQ는 글당 1개였지만 contentMarkdown 조건으로 공개 화면에는 보이지 않았다. FAQ 데이터가 있다는 것과 실제 보이는 것을 구분한다. {question, answer}와 배열형 포맷 차이도 고려해 내용·질문·답변이 실제 HTML과 화면에 모두 표시되는지 확인한다.
- 상품 카드 CTA가 모두 공식몰 홈으로 향했다. 상품별 검증된 상세 URL이 있으면 적합한 상품으로 연결되는지 확인하고, 일반 홈/전화 상담 CTA와 역할을 구분한다. 승인하지 않은 주문은 제출하지 않는다.
- 관련 구매 동선이 충분한지 문서별로 검토한다. 모듈 개수는 목표가 아니며 링크의 목적과 도착지가 실제로 도움이 되는지가 기준이다.

원문뿐 아니라 실제 렌더 결과에서 title/H1/H2/meta, canonical, robots/index 가능성, sitemap, 실제 404, 내부링크, 상품 이미지/CTA, 모바일 읽기·버튼·레이아웃을 확인한다. FAQ와 필요한 안내가 접혀 있거나 숨겨졌다면 가시성과 사용성을 별도로 점검한다. 실제 화면 미검수는 기존 승인된 visual-qa-deferral-policy에 따라 별도 기록하며 PASS로 바꾸지 않는다.

검토한 최종 파일 digest와 source commit, 실제 빌드 및 공개 결과를 결속한다. 원문 변경 후에는 해당 검수와 빌드를 다시 수행한다. IndexNow/GSC 접수, 실제 크롤·색인, 노출, 클릭, 순위는 각각 별도로 기록한다. 공개나 접수 성공을 상위노출 성과로 주장하지 않는다.


## 공통 이미지와 실제 HTML 검사

현재 및 신규 지역 페이지에 [공통 배너와 HTML 구조 기준](SHARED_BANNER_STANDARD.md)을 함께 적용한다. 승인된 동일 이미지 3종과 설명적 alt를 사용하고, H1 1개·H2/H3 순서·출처 구조·title/meta/canonical/robots/sitemap·내부 링크를 실제 HTML에서 검사한다. 배포와 공개 검증이 끝나지 않은 상태를 완료로 기록하지 않는다.
