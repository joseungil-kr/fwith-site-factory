## [추정·판단] 고객이 결정할 일과 페이지 분리

지역 진입 질문은 “광주 동구로 조의를 전하려는데 어떤 상품과 상담을 이용할 수 있나”다. 홈은 가격 범위·한 시설 안내·전화 연결을 짧게 설명한다. 한 상세 글을 홈에서 다시 길게 복제하지 않는다.

시설 상세 질문은 “조선대병원 장례식장으로 보낼 근조화환을 얼마에, 어떤 모습과 문구로 준비할 수 있나”다. 조선대학교병원/조선대병원/조대병원은 한 문서의 동의어로 다루고 URL을 늘리지 않는다. 전남대학교병원은 별개 시설이며 공식 일시 운영중단 문구가 있어 대상으로 넣지 않는다. 금호·남도도 별도 근거 없이 추가하지 않는다.

순서:
1. 조의의 꽃과 상품·리본 상담을 먼저 설명한다. 두 번째 도입 문단에 해당 빈소의 반입·수령·일정 상담 조건을 남겨 현재 정상 운영을 암시하지 않는다.
2. 4개 실제 사진과 기본가로 상품을 비교한다. 크기·꽃 수량·품질은 상품명에서 추론하지 않는다. B201/B203 가격차 20,000원은 확인 가격의 단순 계산이다.
3. 동구 추가비용 표기가 없는 상황에서 기본가와 전체금액을 분리한다. 나주·광양의 10,000원 또는 합산액을 옮기지 않는다. 10만 원 예시는 “상품값 기준 B201/B203”에 한정하고 배송비 포함 주문 예산은 별도 상담으로 남긴다.
4. 공식 주소·전화는 시설 식별에 필요한 한 단락으로 묶는다. 대학 지도는 별도 장례식장 식별 근거다. 지리·역사·빈소 수·주차·동선으로 분량을 늘리지 않는다.
5. 일반적인 짧은 리본 예시와 필요한 주문정보를 설명한다. 특정 감정·종교·고객 경험을 꾸미지 않는다. 전화에서 도와드리는 범위는 상품·리본·주문 상담이다.
6. 본문에서 답하지 않은 구매 질문 3개를 펼친 FAQ로 둔다. 오늘/발인 전 일정, 주문 후 문구 변경·취소, 사진과 다른 소재·파손의 구분이다. 고정 컷오프와 환불보장은 없다.

## 질문 → 답변 → 근거 → 다음 행동

- 상품은 무엇이고 얼마인가: 상세 products + 4카드 → 공식 4SKU 가격·사진 → 해당 SKU 상세 또는 전화
- 배송비 포함 총액인가: 상세 budget → 공식 추가배송비 표에서 동구 미기재, 최종총액 미확정 → 전체 예산으로 주문 상담
- 정확히 어느 시설인가: 상세 facility → 기준일을 밝힌 정부 명부와 대학 지도 → 시설 문의와 꽃이랑 주문 전화 구분
- 지금 그 빈소로 전달 가능한가: lead[1]·FAQ[0] → 현재 운영/반입/시간 미확정 → 주문별 가능 일정 상담. 확정 배송대상 목록으로 승격하지 않음
- 리본에 무엇을 적나: ribbon → 편집자가 제시한 일반 예시와 확인된 상담 범위 → 인사말/보내는 이름 전달
- 변경·취소는 가능한가: FAQ[1] → 제작 완료 제외와 상품 출고 후 취소 조항 양쪽을 정확히 표시 → 개별 주문의 적용조건 상담
- 사진 차이와 파손은 같은가: FAQ[2] → 공식 정책은 소재 차이와 불량·파손·전혀 다른 상품을 구분 → 문제와 주문 내용을 설명하는 상담
- 장례 후 수거 여부: order 마지막 문단 → 공식 별도 수거 없음 → 시설 처리안내 참고. 꽃이랑이 현장 처리 책임을 대신 맡는 약속 없음

## [직접 확인 / 추정·판단] 외부 경쟁과 내부 형제 검토

연구 담당이 실제 검색한 증거와 3개 원본문서를 보존했다. 원고 작성자는 도도·늑대와여우의 본문과 예도의 상품/주문/시설/FAQ 관련 구간을 다시 읽었다. 별도 검색량·순위를 측정하지 않았다.

- 예도는 상품/리본/주문을 한 흐름에 두지만 현재 반입·빈소 수·설치·시간을 구체적으로 주장한다. 우리 원고는 그 주장을 자사 근거로 채택하지 않는다.
- 도도는 8만 원과 시간/인증사진 약속이 중심이다. 우리 상품 가격이나 사진제공 약속으로 가져오지 않는다.
- 늑대와여우는 무료배송·단시간 도착·광주 토박이/거점·노하우를 강조한다. 자체 실적과 동선처럼 쓰지 않고, 금호 소재구와 전남대 관련 설명도 공식 근거로 취급하지 않는다.

나주/광양/순천 원고 전문을 실제 읽고 구매흐름을 비교했다. 여수/목포는 이번에 기계적 문장·shingle 비교만 했다. 다섯 곳 모두 같은 업체의 4SKU와 정책을 쓰므로 상품·리본·변경 의미는 일부 공통이다. 이것을 0% 의미중복이라고 보고하지 않는다.

동구의 실질 차이:
- 현재 운영을 가정하지 않는 시설별 주문 가능성 상담이 도입에 있다.
- 동구 금액이 표에 없으므로 다른 지역의 확정 추가비용과 합산 예산표 대신 상품값/총액의 경계를 설명한다.
- 공식 캠퍼스 시설과 명부로 병원 장례식장 정체성만 확정한다. 다른 대학병원 중단 문구를 조선대에 전이하지 않는다.
- 제작 완료/상품 출고 후 조항을 구분한 변경 FAQ가 있고, 운영 추정이나 분량 확대용 시설 목록을 추가하지 않는다.

lexical 측정은 body-count-and-overlap.json에 보존한다. 낮은 겹침률을 의미 독창성·SEO 품질의 합격 판정으로 바꾸지 않는다. 최종 문체·구매완결성은 작성자와 다른 검토자가 판단해야 한다.

## [추정·판단] 렌더링 계획

- 홈 /, 상세 /regions/chosun-hospital-funeral-wreath/가 2개 primary 페이지다. 상세 글은 1개다.
- /regions/는 실제 자식 1개인 지원 탐색 페이지다. production noindex,follow, sitemap 제외, 메인메뉴 제외, 배너 0개. 상세의 보이는 breadcrumb 중간 링크가 최소 1 inbound를 제공한다.
- /404.html은 실제 404 응답을 요구한다. noindex,follow, 홈 복구 링크만 두고 canonical과 OG/Twitter 및 마케팅 배너를 생략한다.
- 홈/상세는 message → budget → consultation 3배너를 실질 본문·상품 사이에 분산한다. 승인된 같은 bytes, 1774×887, width:100%/height:auto, lazy/async, 전화 1844-0644가 alt에 한 번이다. 삭제된 공통 캡션은 어느 노출문구에도 복원하지 않는다.
- 세 브랜드 배너의 전화번호는 최신 구체 지침에 따른 승인 정본이다. 이전 범용 이미지 규칙을 이유로 제거하거나 재생성하지 않는다.
- 전 페이지 H1은 하나, 섹션 H2, 상품/FAQ/홈 카드 H3, 출처 H2 하나로 계획한다. FAQ 3문답과 카드 4개를 실제 HTML에서 한 번씩 보이게 해야 한다.
- production 3개 콘텐츠 페이지의 OG/Twitter는 자기 title/description, 검증된 origin + 자기 경로, B201 500×500 원본, twitter summary를 사용한다. 아직 origin/domain은 null이며 실존 주소처럼 표시하지 않는다.
- preview는 모두 noindex,nofollow,noarchive, robots Disallow:/, sitemap 0, IndexNow 없음. production sitemap은 home/detail 2URL만이다.

## [미확인] 완료로 볼 수 없는 범위

원고와 명세 파일은 있지만 실제 HTML, static build, 모바일·데스크톱 화면, 키보드, 공개 HTTP, source commit, Actions, 배포, 검색 접수/색인은 없다. source 테스트나 199개 문서 검사로 이 범위를 PASS 처리하지 않는다.

현재 장례식장 운영, 반입·수령 장소, 일정, 동구 배송비/실제 결제총액, 재고, 전화연결, 주문/환불 적용은 미확인이다. 고객에게 현재 활성 운영·상시접수·도착확정·설치·사진전송을 약속하지 않는다.

정지조건은 이 원고·계획·근거·검증 묶음을 독립 검토에 넘기는 것이다. 연구·문서 검수는 공개 허가나 시설 운영 확인을 대신하지 않는다.

## r2 독립검토 반영

검토자가 지적한 고객용 비용 설명의 작성과정 노출 및 주문목록 뒤 반복을 수정했다. 동구 배송비 표 부재는 이 계획과 SOURCE-MAP의 근거로 남기고 고객에게는 기본가격/배송비 포함 최종금액 상담만 설명한다. 주문목록 뒤에는 아직 정보가 다 정해지지 않아도 제공할 수 있는 상품·리본 상담을 짧게 안내한다. 고유 본문은2,322자(FAQ·마무리포함3,015자)로 줄었다. 필수 구매 질문의 답변은 유지되며2,500자 목표를 맞추기 위한 문장 추가는 하지 않았다. 변경2문장의 실제 diff는 revisions/customer-copy-r1-r2.diff에 있다. 최종 독립판정은 아직 대기다.
