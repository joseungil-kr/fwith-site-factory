# Flower-local-v2 whole-region initial template

Candidate zero-customer, region-neutral runtime. This separate profile does not
replace historical template pins or any existing city source. It has no regional
articles, membership, local claims, record IDs, snapshots, approval values or
domain ownership evidence. It is never a published site by itself.

The initial provisioning contract adapts exactly eight configuration files:
site-config, architecture, publish-manifest, page-map, region-coverage,
region-policy and the two Wrangler configs. The prior six-file adaptation stays
exclusive to the historical profile. An exact unbound template is allowed to
build a noindex home with no regional links. Bound coverage always passes the
unchanged shared schema-2 geography adapter.

A new initial site requires fresh official complete membership, exact raw-byte
hashes and schema-2 candidate coverage. Provisioning grants no content, visual,
snapshot, final-batch or domain approval. Query-first Plan and original content
for every member must pass independent source, intent, first-answer, visual,
product/Catalog and purchase-binding review. Only the existing approved frozen
Publisher may populate customer pages. No preliminary one-page gate applies.

Business Truth, product bytes and provenance are reusable only for the same
flower-fwith brand. Reconcile current Truth and active Catalog before content
review. Inventory dates are source evidence, not new live verification. Local
delivery, acceptance and timing are never implied. Editorial art is explicitly
labeled and must not be represented as a real SKU or delivery proof.

Keep productionApproved false, separate QA/disabled-production Workers, no custom
routes and an empty snapshot ledger. Zero-content production builds fail. After
all frozen customer inputs are reviewed, run complete graph/static/unit/UI and
batch verification, connect the existing authorized fwith subdomain, and publish
the complete initial site once. Bootstrap does not authorize either action.

Run `npm test` and `npm run build` with SITE_INDEXABLE=false for an unbound source.
The full external integration harness additionally tests complete membership,
Publisher snapshots, home/hub/detail metadata, robots, 404 and fail-closed scope,
hash and missing-binding cases. Those synthetic approvals are never source data.
