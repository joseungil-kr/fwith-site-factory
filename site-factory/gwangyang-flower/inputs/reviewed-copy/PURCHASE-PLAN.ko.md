## 네 경로와 발견성·메타 계획

두 주 경로는 홈 `/`와 시설 상세 `/regions/gwangyang-funeral-wreath/`다. 홈은 광양 화환 상담을 시작하는 입구, 상세는 해당 시설의 실제 선택·비용·주문을 다루며 동일 본문을 반복하지 않는다. `/regions/`는 실제 자식 1개의 짧은 안내 페이지로 noindex, sitemap 및 주요 메뉴 제외다. `/404.html`은 기술 페이지다. CoreHubLaunch와 FullLaunch는 NOT_ASSESSED다. 현재 origin·domain은 미지정이며 호스트를 생성하거나 존재한다고 주장하지 않는다.

- 검증된 여수 최종 HTML의 breadcrumb를 직접 읽고, 계획부터 상세의 홈 → 안내 → 현재 상세를 넣었다. 중간 안내의 실제 `/regions/` 링크가 support inbound 1개를 만든다. 홈·support는 상세로 연결한다.
- 홈페이지 이외 실제 공개 내용 페이지 모두 inbound 1개 이상을 검사한다. 404만 의도적 링크 대상에서 제외한다. noindex support도 그래프 검사에서 빠지지 않는다.
- 모든 4페이지 H1은 1개다. 출처 H2는 하나, 상품·FAQ는 해당 H2 아래 H3이며, 홈의 시설 안내 카드도 해당 H2 아래 H3다. 배너 제목·캡션은 만들지 않는다.
- home/detail만 향후 indexable·sitemap 2개에 포함한다. preview는 Core §7의 noindex,nofollow,noarchive 및 robots Disallow:/, sitemap 없음·IndexNow 없음이다.
- 홈·상세·support의 고유 title/description을 OG/Twitter에도 동일 정본으로 연결한다. 기술 404는 canonical과 OG/Twitter·상품이미지·상품카드를 생략하고 오류복구 문구·noindex·홈 링크·HTTP404만 둔다. OG URL과 image URL은 검증된 origin이 생긴 뒤 절대주소로 만든다. 실제 상품 B201 이미지를 양쪽에 같은 bytes와 alt로 재사용하며 새 이미지를 만들지 않는다.
- 공통 배너 세 장은 승인 bytes 그대로 복사하고 설명적 alt 끝에 전화 1844-0644를 한 번 둔다. 홈·상세의 실질 문단 사이로 message → budget → consultation을 분산한다. 단일 자식 support와 404에는 0장이다.
- FAQ 3개는 펼쳐진 본문에 각 1회, 4개 상품 CTA는 해당 상세에 각 1회, 카드 공통 사진 조건 안내는 묶음 아래 1회 노출한다.

위 사항은 계획 검사다. 실제 HTML·모바일 화면·메타 응답·공개 이미지·실제 404는 구현·출시 단계에서 다시 검사해야 한다.
