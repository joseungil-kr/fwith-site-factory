[화면 검수 후속 일괄 처리 — 2026-10-10 사용자 변경 지시]
이 절은 앞의 실제 desktop/narrow 화면 검수가 공개·검색 제출·다음 지역 제작을 반드시 선행해야 한다는 문구보다 우선한다. 사용자는 화면 검수를 나중에 모아서 진행하고 예정된 지역 제작·공개를 계속하도록 승인했다.
- 원문·출처·상품·독립 내용검토·고정 source 무결성·빌드·정적/HTTP·canonical·robots·sitemap·404·내부링크·이미지 파일 검증은 그대로 수행한다. 실제 화면 검수만 후속으로 이관할 수 있으며 미검수는 PASS로 기록하지 않는다.
- 화면 검수가 미완료이거나 검수용 브라우저가 연결되지 않아도, 나머지 공개 기준을 충족하면 기존 정식 경로로 공개하고 IndexNow 및 GSC 사이트맵 제출을 수행한다. 서비스 필수 승인, 보안·권한·credential·DNS 소유권 경계를 우회하지 않는다.
- 기존 main checkpoint에 deferredVisualQa 배열을 보존한다. 항목마다 지역/scope/branch/root/Worker/hostname, exact source 및 원문·이미지 digest, 원래 계획 N/합격/보류 수, 공개 URL/run/HTTP 검사/IndexNow/GSC 증거, 아직 확인하지 않은 desktop/narrow route 목록과 항목, 마지막 관측과 실제 원인 미확정 여부, 후속 검수 상태를 기록·재조회한다. 새 실행 프레임워크나 예약·감시자는 만들지 않는다.
- 공개 및 HTTP 검증과 검색 제출이 확인된 지역은 released_search_submitted_visual_qa_deferred로 구분하여 중복 제작·배포·접수를 방지하고 다음 기존 호출의 다음 미개설 지역 진행을 허용한다. 전체 화면 검수까지 완료한 것으로 합치지 않는다. 현재 호출에 아직 신규 지역을 맡지 않았다면 남은 승인 범위 안에서 다음 후보 한 지역을 시작할 수 있다.
- 화면 오류 자체가 확인된 경우 구체적인 영향과 안전한 수정 필요성을 기록한다. 개인정보 노출·보안·잘못된 상품/CTA·깨진 핵심 경로 등 다른 필수 검증 실패를 단순 화면 대기로 숨기지 않는다.
