[추정·판단] 동결된 광산구 고객 원고와 출력 계획은 원고 단계에서 수용한다. 사실·정책의 표현, 제공자 문체, 구매질문 완결성, 검색 의도 분리를 각각 새로 판단했다. 수정이 필요한 원고 차단결함은 발견하지 않았다. 이 판단은 실제 HTML·앱 구현·화면·공개·색인 검증을 대신하지 않는다.

## 문체·친절함의 새 판단

[추정·판단] 원고 문체를 다음과 같이 수용한다. 기계검사 또는 글자수로 이 판단을 대신하지 않았다.

- 제공자 화자: 꽃이랑이 상품·리본·총예산 상담을 이어가는 말투다. 독자에게 자료를 확인하고 돌아오라는 책임을 반복해서 넘기지 않는다.
- 공감과 스몰토크: 조문을 대신하거나 뜻을 더해 전하는 상황, 길게 적기 어려운 인사, 예산이나 인사부터 시작하는 설명이 차분하다. 고객의 실제 감정·기억·경험을 단정하지 않는다.
- 선택 도움: 사진의 관찰 가능한 차이와 기본가를 연결한다. 높은 가격을 큰 정성이나 우월한 품질로 연결하지 않는다.
- 주문 부담: 필요한 내용은 네 항목 한곳에 모였고, 미정인 정보가 있어도 알고 있는 내용부터 상담할 수 있다고 설명한다. 주소·명의의 기본 개념을 가르치거나 가상의 오배송 사례를 만들지 않는다.
- 제한과 도움의 균형: 비용·현장일정·주문후 정책을 해당 위치에 배치했다. 경고가 도입을 차지하지 않고 CTA 전후로 같은 금지사항을 반복하지 않는다.
- 표현 반복: 상담이라는 핵심 행위는 여러 위치에 나타나지만 모든 문단이 같은 명령이나 감성 문장으로 끝나지 않는다. 본문 내부 긴 문장의 완전 반복은 없다. 동일 카드 배송 라벨은 의도적인 기능적 재사용이다.
- 짧은 문맥: 지원목록·404·버튼·메뉴·푸터는 각각 탐색/복구/연락에 맞는 중립 문구다. 모든 작은 UI에 감성 스몰토크를 강제로 넣지 않았다. 404에 마케팅 배너나 새 서비스 약속을 만들지 않는다.

## 구현에서 반드시 검증할 사항

[미확인] 실제 HTML, 브라우저 픽셀, 키보드·모바일, 공개 HTTP는 아직 없다. 출력 계획은 다음 요구를 포함하지만 구현 증거가 아니다.

- 실제 네 경로를 분모로 유지한다. 홈/상세만 검색대상이고 지원목록은 noindex, sitemap 제외다. 알 수 없는 주소는 실제404여야 한다.
- 각 페이지 H1 하나, 순서가 맞는 H2/H3, 출처 H2 하나, 페이지별 title/meta/social을 검사한다. 고객 원고의 문자열이 의도한 본문·접근성·메타 위치에 나오는지 확인한다.
- origin/도메인/실제 canonical은 아직null이다. 검증된 공개 origin에 결속한 뒤 각 정상경로의 자기 canonical을 검사하고 기술404의 canonical은 생략한다.
- 홈·상세에 배너 message→budget→consultation 사이 실질 내용이 있어야 한다. 단일 지원목록과404는 배너0개를 유지한다. 원래 적용하지 않는 단일 목록에 helper를 이유로 배너를 강제로 붙이지 않는다.
- 상품4카드와 FAQ4질문/4답변은 상세 HTML에서 각각 한 번 실제 보이고 FAQ는 접히거나 contentMarkdown 조건에 가려지지 않아야 한다. 제품 예시 고지는 유지하고 삭제된 배너 공통 캡션은 복원하지 않는다.
- SKU별 외부 CTA, tel:18440644, home→detail, detail→support→detail, sources fragment를 실제 링크 그래프로 검사한다. 실제 전화/주문 완료는 별도 행위다.
- 정확한 배너 bytes/MIME/크기/alt, 제품사진의 비율·잘림, 메뉴·스크롤·버튼·focus 및 모바일 읽기를 검증한다. source tests/build/negative tests와 원격 readback, 최종 산출물·source commit 결속이 필요하다.
- 공개 URL의 응답·자산을 별도 검사한 뒤 필요한 IndexNow 접수를 검증한다. 영수증과 실제 색인/순위는 구분한다. CoreHubLaunch·FullLaunch는 NOT_ASSESSED다.

## 남은 한계와 실패 기록

[미확인] 최종배송비·결제총액, 현재 재고/운영/전화응답, 실제 빈소배정·외부화환 반입/수령·설치·사진 제공·특정 도착·환불 이행은 확인하지 않았다. 시설/상품 게시자료의 확인과 실제 주문 이행을 구분한다.

제품 HTML 텍스트 추출의 첫 시도는 `ModuleNotFoundError: No module named 'bs4'`로 실패했다. 설치나 접근범위 변경 없이 이미 있는 lxml로 네 원본을 모두 읽어 복구했다. 이 오류는 원고 결함이나 사용자 취소로 해석하지 않았다.

검토 파일에는 패키지 상대경로·허용된 사업/시설 출처·해시만 사용한다. 경쟁사 원문/사진, 원시 계정 메타데이터, 개인정보/부고, 비밀값은 새 공개 후보에 복사하지 않는다. 원본 연구 전체를 공개할 수 있다는 허가가 아니며, 이 검토 폴더 역시 고객 HTML에 렌더하지 않는다. 원격 쓰기·PC·Codex/Work·cloud task·content API·주문·전화·결제는 수행하지 않았다.

- `current-main-guidance-readback.json`: 새로 가져온 네 GitHub 원문과 기존 바이트 대조
- `independent-audit.json`: 원본61파일,159/24/2 분모,117문구,13질문,4FAQ,자산과 중복 재계산239항목

- `customer-context-review.json`:117문구 및 배너 이미지 문구의 새 문체/문맥 판단
- `question-review.json`:13질문의 새 답변·근거·다음행동 평가
- `review-result.json`, `review-bindings.json`, `review-manifest-r1.json`: 원고·계획·원본·새 검토 결과의 결속

원고나 출력 계획을 바꾸면 이 결과를 자동 승계하지 말고 수정분을 포함한 전문·문맥·관련 근거를 다시 검토해야 한다.
